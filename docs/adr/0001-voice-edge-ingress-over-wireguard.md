# 跨区域语音加速：无状态 Edge Ingress 经 WireGuard 回源

海外用户直连国内主服时，语音（含摄像头与屏幕共享）的丢包与延迟高到不可用；而网页、API、WebSocket 信令与文件对延迟不敏感，无需改动。因此只加速 WebRTC 媒体面：国内维持单主服单 Voice Runtime，海外节点作为无状态的 Edge Ingress 接入媒体流量，经 WireGuard（CN2 专线）与内核转发回源到主服复用的单端口 WebRtcServer；主服按客户端所选节点改写下发的 ICE candidate，未选节点的客户端保持直连。节点列表配置在国内服务端配置文件（支持环境变量覆盖），客户端默认直连、手动选节点并本地持久化。

## Considered Options

- **coturn TURN 中继（经 WireGuard 回源）**：虽可经 WireGuard 走专线并支持 TURN-TLS 443 穿透，但每新增一台海外节点都要部署维护 `coturn` 进程、共享密钥与白名单防滥用，开 443 还需配域名和证书续期，并引入用户态中继与额外握手开销。
- **mediasoup PipeTransport 级联多 SFU**：海外节点要运行完整媒体栈并持有房间状态，从无状态入口升级成分布式 SFU，开发与运维复杂度远超收益。
- **Discord 式按房选区**：每个语音房间固定归属一个区域，跨区成员必然有人劣化，还需按房间路由媒体与归属状态，粒度太粗。
- **节点入库 + 后台管理页 + 角色权限门禁**：节点列表低频变更，配置文件加环境变量覆盖足够；为此建表、建 CRUD 与权限体系属于过度工程。

## Consequences

- 选中有效节点后，客户端严格只使用该节点的 ICE candidate，不与国内直连候选混流，避免劣化路径静默混入；节点被配置移除时自动回退直连并提示。
- 新增欧洲、美洲、澳洲等节点只改国内主服配置并重启，无需发版，无需数据库变更。
- 海外服务器零业务进程、不持有任何会话状态；但企业防火墙仅放行 443/TLS 的极端受限网络暂不覆盖（未含 TURN-TLS 穿透），未来如遇此类场景可按需扩展。
